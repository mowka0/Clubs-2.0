## 2. Что сделано за сессию

**Оплата клуба участником** (решения PO, спека `billing-member-pays.md`):
- платит любой активный участник, **разово** (карта не сохраняется); автопродление — только с карты
  владельца, оплата участника сдвигает его на 30 дней;
- плашка подписки на главной клуба — **всем, когда пора платить** (`paymentDue`: ≤ 7 дней МСК до
  конца, грейс, не оплачено); оплаченный клуб — только в «Управлении»; пока автосписание в пути —
  кнопки нет (защита от двойной оплаты);
- крайний оплативший — «Последний платёж — Имя 💛» и 💛 в «Участниках»; не-владельцу +10 надёжности
  (`club_billing_paid`, вес как посещённая встреча — PO оставил), не чаще раза в 30 дней;
- оплата во время бесплатного периода — месяц от **конца** бесплатного периода;
- напоминания — только владельцу; неактивный ползунок автопродления убран (строка «включится при
  следующей оплате картой»); фраза «Оплатить может любой участник» убрана;
- оферта: Заказчик — и участник; п. 3.3 и 3.4.

**Этап 1 «только чат»** (решения PO, `stage-1-scope.md`):
- спрятано флагами `config/productProfile.ts`: создание с нуля («+ Клуб» → сразу выбор чата),
  взносы и «Финансы», тип доступа и заявки, категория; код и API не удалены;
- лимит клуба из чата **500** (PO выбрал против «лимит = размер чата + заявка на расширение»);
  полный клуб — «Клуб заполнен — напиши организатору»; чип «N участников»; лимит в «Настройках» 1–500;
- V104: клубам из чата лимит 500; все `closed` → `private` со сбросом `apply_invite_code`;
- бот: «🎉 Ты в клубе «…»!», стучащемуся «Вступи в клуб в приложении — и я впущу», имя ссылки-двери,
  личка со-организатору, `/start`; карточка приглашения без категории.

**Правки с прогона 10.10** (`a98dfe21`, ждут перепроверки PO):
- функции чата (живой закреп, статус сборов) включаются **сразу по правам**, а не при первом показе;
- шторка «Клуб создан» — только пока клуб не закреплён в чате;
- пост в чат: «В чате болтаем, а в клубе организуем. Вступай в наш клуб, чтобы быть всегда в курсе
  происходящего 🔥»;
- «Пригласить в клуб» без «Приглашение уйдёт от вашего имени»;
- превью «Встречи и сборы»: правило 1 — механика встреч, правило 2 — сборов;
- «Событие» → «Встреча» во всём интерфейсе; «Создать встречу» / «Создать сбор» открывают меню

## 6. Рецепты

**Деплой staging — ждать по очереди Coolify:**
```bash
ssh root@77.42.23.177 "docker exec coolify-db psql -U coolify -d coolify -At -c \"select id, status, left(commit,8) from application_deployment_queues where application_name='clubs2-staging' order by id desc limit 3\""
```

**Полная очистка staging** (так делали 09.10): дамп → через Bot API токеном из контейнера бэкенда
`deleteMessage` закрепа клуба, `revokeChatInviteLink` двери, `leaveChat` (бот выходит из группы) →
`TRUNCATE … CASCADE` всех таблиц, кроме `cities`, `interests`, `subscription_pricing`,
`flyway_schema_history` → `redis-cli FLUSHALL` → рестарт бэкенда. Сообщения бота в группе, кроме
закрепа клуба, вышедший бот удалить не может.

**Кодоген jOOQ** — вспомогательная база `clubs_codegen` в локальном `clubs2_postgres` пересобирается
из всех миграций (`sort -V`, psql), затем
`DB_URL=jdbc:postgresql://localhost:5432/clubs_codegen ./gradlew generateJooq --rerun-tasks`.
