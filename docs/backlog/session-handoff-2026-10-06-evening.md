## 2. Решения PO этой сессии (в коде явно не видны)

1. **Автовключение:** закреп встреч и статус сборов — только у клуба, уже показанного в чате
   (есть закреп со ссылкой); у клуба из чата их включает **первый** «Показать клуб в чате».
   Теги — сразу по праву. **Вход по заявкам и строгий режим сами не включаются никогда.**
2. **Клуб из чата молчит до показа** — первая встреча при наполнении не должна уйти в чат с пушем.
3. **Обращение:** приложение на «ты», биллинг (полоска, шит, DM о подписке) на «вы».
4. **Каталог и всё про «много клубов»** (Поиск, список клубов) — отложено; тексты C5–C8, D4–D13
   таблицы не трогаем.
5. **Занятый чат** («уже привязан к другому клубу») — оставить как есть: в группу бот не пишет,
   отказ в личку; «приветствие», которое видел PO, — старый закреп бота, Telegram открывает группу.
6. Перебросить человека из Telegram в личку бота после выдачи прав **нельзя** (у Bot API нет
   такого действия) — дорога только через DM и шторку.

## 6. Ловушки сессии

- **Док и «назад» взаимоисключают друг друга**: `Layout` зовёт `useBackButton(!showTabBar)`. Экран,
  открытый кнопкой изнутри, должен жить на адресе БЕЗ дока — иначе нативного «назад» нет (так
  появился `/connect-chat` вместо «/»).
- **`NewClubFromChatGate` перенаправляет** при первом открытии после создания клуба из чата — любой
  параметр в адресе, который должен дожить, надо прокидывать и через него.
- **Две `Modal` telegram-ui одновременно** — не открывать: окно «Чат подключён» (`ChatSetupGate`) и
  шторка «Клуб создан» могут совпасть; сейчас окно у клуба из чата всплывает только при нехватке
  обязательных прав.
- **Тест «адрес совпал»** проходит ДО перехода, если стартовый адрес уже правильный — ждать побочного
  эффекта гейта (стёртая отметка), потом проверять.
- **Kotlin**: имя теста в бэктиках не может содержать `;`.
- **zsh**: `rm -f tsconfig*.tsbuildinfo` без совпадений роняет ВСЮ команду (nomatch) — кэш `tsc` не
  удаляется молча. Использовать `find . -name '*.tsbuildinfo' -not -path './node_modules/*' -delete`.
- **Не пушить в ветку, пока собирается прод** (две сборки кладут VPS 3,8 ГБ) — проверять очередь:
  `docker exec coolify-db psql -U coolify -d coolify -Atc "select id,status,left(commit,8) from application_deployment_queues order by id desc limit 3"`.
- Полный `vitest run` иногда валит файл на загрузке модуля (тесты все зелёные) — повторный прогон чистый.
