# POST /api/subscriptions выдаёт платный план бесплатно

**Статус:** открыт, обязателен к закрытию **перед подключением ЮKassa**
**Severity:** High (в момент включения реальных денег — Critical)
**Заведён:** 2026-08-16, разбор модели подписки в рамках спринта 1.0

## Суть

`POST /api/subscriptions` доступен любому авторизованному пользователю: в
`SecurityConfig.kt:45` весь `/api/**` закрыт только `authenticated`, отдельной
проверки на этом эндпоинте нет. За ним стоит `StubPaymentProvider.kt:23-32`,
который возвращает фиктивный токен `stub-<uuid>` и `current_period_end = now + 30
дней`, ничего не списывая.

Итог: один запрос — и у пользователя активная подписка с максимальным планом,
без единого рубля.

## Почему сегодня не горит

Платных клубов в проде нет, а после разворота на чат-модель клуб из чата
рождается бесплатным (`subscription_price = 0`). Выданный план ничего не
открывает: гейт `requirePaidClubCapacity` вызывается только внутри
`if (request.subscriptionPrice > 0)` (`ClubService.kt:93-95`, `:258-260`).

## Почему станет критично

В момент, когда `StubPaymentProvider` заменят реальным провайдером (ЮKassa),
этот же эндпоинт останется способом получить оплаченный период в обход кассы.
Дыра из безвредной превращается в обход оплаты в один HTTP-запрос.

## Что сделать

- Закрывать **одновременно** с подключением эквайринга, не после.
- Подписка должна создаваться только по подтверждённому платежу провайдера
  (вебхук с проверенной подписью), а не по запросу клиента.
- Идемпотентность уже есть — `subscription_event.provider_event_id UNIQUE`
  (`V35:61-62`), переиспользовать её.
- Проверить заодно `POST /api/subscriptions/cancel` и путь даунгрейда на те же
  права вызова.
