## 1. CSP-заголовок в nginx (расширение доверия к третьей стороне)

Фича впервые вводит исполняемый third-party код: JS API Яндекса грузится скриптом с
`api-maps.yandex.ru` и получает полный доступ к DOM/памяти страницы (JWT живёт в
Zustand-памяти). CSP-заголовка в `frontend/nginx.conf` нет вообще (pre-existing).

Предлагаемый заголовок (devops-задача, проверить на staging — не поломать аватарки/uploads):

```
Content-Security-Policy:
  script-src 'self' https://api-maps.yandex.ru;
  connect-src 'self' https://geocode-maps.yandex.ru https://api-maps.yandex.ru;
  img-src 'self' data: https://static-maps.yandex.ru;
```

(плюс текущие хосты аватарок/загрузок — проверить фактические источники img.)

## 2. ✅ Quota-burn DoS на создание событий — ЗАКРЫТО 2026-08-05

Было: ключ геокодера публичный (в бандле), referer-ограничение обходится вне браузера
(`curl -H "Referer: ..."`). Выжигание лимита 100 запросов/сутки → геокодер отдаёт ошибки →
из-за fail-closed организаторы не могут создавать события до конца суток.

Предполагалось сделать «при росте масштаба / первом инциденте» — инцидент случился:
в проде поиск адреса лёг, потому что прод-домена не было в белом списке ключа, а клиенты
с закэшированным бандлом (`immutable` на год) продолжали слать старый ключ, и починить это
со стороны сервера было нечем.

Сделано: **серверный прокси** `GET /api/geo/geocode` (`GeocoderService`), ключ уехал в env
бэкенда и вычищен из бандла, Dockerfile, compose-args и `vite-env.d.ts`. Разбор и решения —
`docs/modules/event-geo.md` § «Почему геокодер переехал на сервер».

**Осталось от этого пункта:** отдельного rate-limit по user_id на геокодинг нет — эндпоинт
живёт под общим лимитом `RateLimitFilter` (60/мин на пользователя). Квота Яндекса теперь
тратится только авторизованными пользователями, а не кем угодно с ключом из бандла, но
адресный лимит именно на геокодинг стоит завести, если увидим выжигание.
