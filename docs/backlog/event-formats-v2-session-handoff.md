## 2. Что сделано (кратко)

Бэкенд: `V86` (min_participants, roster_decided_at, roster_warning_sent_at, DROP limit_kind);
`EventFormat` NORMAL/OPEN по `participantLimit == null`; `EventFormatInput` принимает литералы V85;
`RosterPolicy` (одна формула + `DeclineConsequence` + `RosterSchedule`); `RosterService` (① по

отказа/кика/выхода, сброс напоминаний в `closeRoster`); `POST /api/events/{id}/proceed`;

(`roster:proceed:` / `roster:remind:`), DM ②/③ с кнопками; env `ROSTER_WARNING_MINUTES_BEFORE_DEADLINE`.
Фронт: пикер из двух карточек, `RosterLimitsFields` + `useRosterLimits`, засечка минимума на кольце,
полосы статуса, «Проводим», таб «Без ответа» на наборе, диалог отказа по `declineConsequence`,
бейджи «👥 4–10» / «👥 До 10» / «👥 Ровно N» / «🌊 Открытая». Доки выровнены, спека —
`docs/modules/event-formats.md`.

**2026-09-05, до прогона (решение PO):** режим «дата ближе интервала → набор закроется сразу, места
первым» **убран целиком**. Одно правило: у встречи с местами дедлайн набора обязан быть в будущем,
иначе 400 «До встречи меньше N ч — набор не успеет закрыться. Подвиньте время встречи.» и в форме
та же ошибка (плюс «или выберите интервал короче»). Из фронта ушли: гашение минимума, подпись
«Оставьте только максимум», недоступные насечки, автоподбор интервала, ⚡-строка в шторке. Срочная
встреча — будущий отдельный формат (спека § 15). Правка: `EventService.requireRosterFitsBeforeStart`,
`RosterLimitsFields`, `EventForm`, `EventPage`; тесты обновлены.

## 4. Ловушки

- **Serena Kotlin-LSP не поднимается** (таймаут инициализации) — навигация grep/cat.
- **Локальная БД:** `flyway_schema_history` заканчивается на ранге 76, схема при этом V86 (V77–V86
  применялись `psql` мимо Flyway). Локальный `bootRun` упадёт на валидации; лечится
  `docker compose down -v` и чистым стартом. Для `generateJooq` достаточно схемы.
- **jOOQ KotlinGenerator:** конструктор `UsersRecord()` приватный — в тестах `mockk<UsersRecord>`.
- **`EventFormatInput` обязан иметь `@JsonValue`** на литерале: иначе `writeValueAsString` шлёт
  `NORMAL`, а `fromWire` его не знает → 400 в интеграционных тестах.
- **Цикл `RosterService → EventService`:** отметку ② при create/PUT считает `EventService` через
  чистый `RosterSchedule`.
- **Тексты закрепа** проверяют `LivePinServiceTest` и `LivePinRendererTest` — при смене словаря
  `formatName` менять оба.
- **mockk:** `any<T>()` у `publishEvent(Any)` матчит любое событие — для `verify(exactly = 0)`
  использовать `ofType(T::class)`.
- **`participant_limit IS NULL`** читают пять мест как маркер открытой встречи — потолок nullable
  не делать.
- **Ловушка окружения staging:** встреча без своего интервала в форме пишет «за 18 ч», а сервер
  закрывает набор за 4 минуты — форма знает только прод-дефолт.
- **`declined` терминален:** отказавшийся не может вернуться в состав, поэтому повторное ③ после
  возврата состава (AC-5) руками не воспроизвести — только юнит-тесты.
- Фронт: `useRosterLimits` гасит минимум эффектом при `minUnavailable`; после возврата даты минимум
  остаётся выключенным — осознанно.
