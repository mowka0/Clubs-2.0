Удалить как мусор: `ROSTER_SHORTFALL_RESPONSE_MINUTES`, `ROSTER_DEADLINE_MIN_LEAD_MINUTES`,
`TRAEFIK_SERVICE_NAME`. После правок — редеплой. Проверка, что env доехал: создать встречу без
своего интервала — шкала в форме покажет «за 18 ч», а `~/clubs-fast.sh show` покажет `lead` пустым,
и набор закроется за 4 минуты до старта (это ловушка окружения, не баг: форма знает только
прод-дефолт).

**Скрипт `~/clubs-fast.sh`** (обновлён под V86 и новые тайминги, правит ПОСЛЕДНЮЮ созданную
встречу «Партии», пока она в наборе):

| Режим | Что делает | Зачем |
|---|---|---|
| `show` | последние 5 встреч: лимит, минимум, интервал, «Проводим», отметка ② | сверка состояния |
| `warn` | старт через 8 мин, дедлайн через 4, ② через ~1 мин | правило ② и ① |
| `early` | дедлайн через 1 мин, старт через 71 | отказы после закрытия «ранние»: −100 / 0 |
| `late` | старт через 3 мин, состав закроется на ближайшем тике | с **+1 до +3 мин** отказы «поздние»: −50 / −150; успевает явка |

Скрипт выставляет отметку ② так, как сделал бы сервер при переносе даты: `warn` — пусто (момент
впереди, тик пришлёт DM), `early`/`late` — «уже израсходовано» (DM не будет). Без скрипта то же
самое делается прямым `UPDATE events SET event_datetime = …, stage2_lead_minutes = …,
roster_warning_sent_at = …`.

Каждый кейс создаётся с датой «через час» и любым интервалом, потом двигается скриптом — так форма
не мешает гардом даты.

## 1. Люди и репутация

Клуб «Партия» (`7ab34ae8-…`), чат «Опат», живой закреп включён, бот администратор. Активных
участников трое:

| Кто | Роль | Исходов | Сдержал (вес) | Нарушил (вес) | Надёжность сейчас |
|---|---|---|---|---|---|
| **Ivan** (`varlamov_ivan`) | организатор | 3 | 0 | 2,16 | — не показывается: владелец в своём клубе |
| **Clubs** (`clubs_tech_support`) | со-организатор | 35 | 15,46 | 9,09 | **49** |
| **XX \|** (`xxx_xxx_xx1`) | участник | 25 | 9,69 | 9,33 | **39** |

Ivan — третье тело для составов и очереди, его число не проверяем. Все ожидания про репутацию —
только Clubs и XX.

**Формула** (байесовская доля сдержанных обещаний с затуханием, цена промаха работает весом):

```
надёжность = round(100 × (сдержано + 2,55) / (сдержано + 2 × нарушено + 3))
вес сдержанного = 1,0 за исход;  вес нарушенного = |очки| / 100
затухание: × 0,5^(возраст в днях / 90)
```

Очки: явка +100, спонтанная явка +100, оплата сбора +10 (все — вес 1,0); неявка −200 (вес 2,0),
поздний отказ без замены −150 (1,5), ранний отказ без замены −100 (1,0), поздний отказ с заменой
−50 (0,5), просрочка сбора −40 (0,4). Бесплатный отказ и выход на наборе строки в леджере **не
создают** и число не двигают.

**Сколько даст один свежий исход от сегодняшней базы:**

| Исход | Clubs 49 → | XX 39 → |
|---|---|---|
| пришёл (+100) | 50 | 41 |
| поздний отказ, замена есть (−50) | 48 | 38 |
| ранний отказ, замены нет (−100) | 47 | 37 |
| поздний отказ, замены нет (−150) | 45 | 36 |
| не пришёл и не предупредил (−200) | 44 | 35 |

Просадки маленькие, потому что история большая (35 и 25 исходов): один промах двигает число на
1–5 пунктов. Это правильно, так один срыв не клеймит человека с track record.

**Цена отказа из закрытого состава** (одна формула для всех):

| Ситуация | > 2 мин до старта | ≤ 2 мин |
|---|---|---|
| замена в очереди есть | 0 | −50 |
| замены нет, состав остаётся не ниже обещанного | 0 | 0 |
| замены нет, состав падает ниже обещанного | −100 | −150 |

Обещанное — минимум, если он включён; без минимума обещанием считается каждое занятое место.
Пока идёт набор, выход бесплатен всегда.

## 8. Как пересчитать самому

```
PG=$(ssh root@77.42.23.177 "docker ps --format '{{.Names}}' | grep '^postgres-u91a5392'")
ssh root@77.42.23.177 "docker exec -i $PG psql -U clubs -d clubs" <<'SQL'
select u.first_name, count(*) as outcomes,
  round(sum(case when kind in ('ironclad','spontaneous','skladchina_paid')
       then power(0.5, extract(epoch from (now()-occurred_at))/86400/90) else 0 end)::numeric,3) as kept,
  round(sum(case when kind in ('no_show','spectator','skladchina_expired','abandoned_slot',
                               'late_decline_covered','late_decline_uncovered','open_no_show')
       then abs(points)/100.0 * power(0.5, extract(epoch from (now()-occurred_at))/86400/90) else 0 end)::numeric,3) as broke
from reputation_ledger l join users u on u.id=l.user_id
where l.club_id='7ab34ae8-c8e0-42e5-8a78-aeaed67d267a'
group by u.first_name order by u.first_name;
SQL
```

Дальше: `надёжность = round(100 × (kept + 2,55) / (kept + 2 × broke + 3))`. Имя контейнера меняется
при каждом редеплое — всегда добывать подстановкой.
