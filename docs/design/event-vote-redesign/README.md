# Редизайн блока «Набор» на странице события

Черновик дизайна (мокапы), кодом ещё не реализовано. Мокап: [`mockups/vote-block-variants.html`](mockups/vote-block-variants.html)
— открывается в браузере, кликабельный: голос переключается, счётчики и шкалы пересчитываются.
Переключатели вверху: наполнение (пусто / 12 из 20 / почти полно / открытая встреча) и тема (тёмная / светлая).

Затрагивается только Этап 1 (голосование «Пойду / Возможно / Не пойду»), верстка —
[`EventPage.tsx`](../../../frontend/src/pages/EventPage.tsx) (блок `rd-vote-layout`) и стили `rd-vote-*` / `rd-donut`
в [`redesign.css`](../../../frontend/src/styles/redesign.css).

## Что не так с текущим блоком

1. **Кольцо и число внутри него считают разное.** Дуга — доли голосов (`going : maybe : not_going`
   от суммы голосов), число — заполненность мест (`goingCount / participantLimit`). Визуально они
   выглядят как одно целое, поэтому дуга читается как «сколько мест занято», хотя это не так.
2. **Счётчики продублированы**: те же числа в кнопках и в кольце.
3. **Дорого по высоте**: ~210 px до списка участников, из них 168 px — кольцо.
4. **«Возможно» и «Не пойду» визуально равны «Пойду»**, хотя ценность этих действий для набора разная.

## Решения PO (2026-08-01)

- **Палитра — наша** (иду оранжевый / возможно фиолетовый / не иду серый). «Светофор» из референса
  (зелёный / оранжевый / красный) отвергнут; переключатель в мокапе оставлен только для сравнения.
- **Круг равен по высоте стопке кнопок.** В реализации это значит фиксированную высоту кнопки
  (42 px × 3 + 2 зазора по 7 = 140) и круг 140 px — вывести диаметр из содержимого нельзя,
  получается циклическая зависимость размеров.
- **Блок «Кто откликнулся» с табами** по статусу вместо нынешних «Предварительных голосов»:
  сейчас видны только идущие, а лиц за «возможно» и «не иду» нет нигде.
- **Онбординг-шторки на экране события не будет** — экран понятен и так.
