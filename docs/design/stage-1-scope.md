# Этап 1 «только чат»: что прячем из интерфейса

> PO 2026-10-09. Стратегия в три этапа:
> 1. **Приложение только для Telegram-чата** — набрать аудиторию, 199 ₽ в месяц за клуб.
> 2. **Каталог и поиск клубов** — когда наберётся критическая масса: приватность, репутация клуба,
>    кросс-репутация участников.
> 3. **Клубы по интересам** — создание клуба с нуля, платное участие, платные фичи владельцам.
>
> На этапе 1 все клубы рождаются из чата друзей, вступают бесплатно, друг от друга изолированы.
> Фичи каталога в интерфейсе только мешают: выбор, которого в дружеском чате не бывает, лишние
> ветки в тестах, вопросы в поддержку.

## Решения PO

| Фича | Этап 1 | Почему |
|---|---|---|
| Создание клуба с нуля | **спрятать** | клуб рождается только из чата; с нуля — для каталога (этап 3) |
| Платный клуб: взнос, цена, «Финансы», шторка взноса, статусы «ждёт оплаты» / «подписка истекла» | **спрятать** | в дружеском чате вступают бесплатно; общие деньги — сборы |
| Тип доступа (открытый / закрытый / приватный) и заявки в клуб | **спрятать** | клубы изолированы и создаются на доверии |
| Лимит участников | **оставить** | PO 2026-10-09; но починить расхождение: форма 1–80, клуб из чата — до 500 |
| Город | **оставить** | нужен для статистики перед этапом 2 |
| Интересы / темы клуба | **оставить** | наполненность клуба |
| Категория клуба | **решить** | инвентаризация показывает, где видна |
| Надёжность внутри клуба, приглашения, со-организаторы, сборы | **оставить** | держат встречи и деньги; межклубная репутация — этап 2 |
| Подписка владельца за чат (199 ₽, Robokassa) | **оставить** | модель монетизации этапа 1 |

## Как прячем

**Прятать, а не удалять.** Интерфейс прячется флагами; сервер меняется только там, где без этого
нельзя (лимит, тексты бота, миграция данных V104 — см. «Спецификация» ниже): на этапе 2 фичи
включаются обратно. Переключатель один — `frontend/src/config/productProfile.ts` (так уже
спрятан каталог): профиль получает признак этапа, экраны читают его, а не заводят свои флаги.

Отдельно проверить фичи, которые срабатывают **без интерфейса** (шедулеры, личка бота):
напоминания о продлении членства, автоотказ заявок, заморозка после вступления в платный клуб.
Бот не должен писать про то, чего человек в приложении не видит.

#### 0. Главное

**Как рождается клуб из чата** (`B/club/JooqClubRepository.kt:113-133`, `B/club/ClubService.kt:128-155`):
- `access_type=private`, `subscription_price=0`, `category=other`, `application_question=null`.
- `member_limit` равен числу людей в чате, от 1 до 500.
- Вступившие получают `active` с `subscription_expires_at=NULL` (`B/membership/MembershipService.kt:306-318`).
- Из UI «с нуля» клуб может быть только `open` или `closed`. `private` возможен только из чата.

**Выводы:**
1. Группы 2 и 3 (взносы и заявки) для клуба из чата не срабатывают сами. Все триггеры привязаны к данным, которых у такого клуба нет: `price>0`, `subscription_expires_at`, pending-заявки. Шедулеры молчат.
2. Но в UI у клуба из чата уже торчат чипы «Приватный», «N / M», «Бесплатно», категория «Другое» и поля цены, лимита и «Тип доступа» в настройках.
3. **Есть одна реальная протечка в заявки: «клуб полон».** Лимит выставлен по размеру чата (в E2E «3 человека + бот = 4»). Когда чат вырос, вступление даёт ошибку «Club is full». UI предлагает «Попроситься в клуб», и это единственный путь к `applications` у клуба из чата. Сервер принимает заявку в полный клуб при любом `accessType` (`B/application/ApplicationService.kt:56-62`). Поэтому группу 4 нельзя спрятать без изменения бэкенда (раздел 9).
4. **«Вход в чат через заявки» технически не связан с `accessType`.** `chatlink/` и `bot/` вообще не читают `accessType` и таблицу `applications`.
   - `ChatDoorService.onChatJoinRequest` решает по статусу membership и флагу `door_enabled`, который по умолчанию выключен. Он включается только вручную и требует право `canInviteUsers` (`ChatLinkBotService.kt:374`, `ChatLinkService.kt:350-360`).
   - Это Telegram-заявка в чат, а не заявка в клуб. Фича остаётся.
   - Слова «заявка» и «одобрит организатор» живут только в текстах: UI таба «Чат», DM бота, имя пригласительной ссылки (раздел 6).
5. `ClubCreatedSheet` — шторка клуба **из чата**, она остаётся. Ветка «клуб создан с нуля» не в шторке, а в `F/components/CreateClubModal.tsx:204-255`. Она исчезает вместе с формой.
6. Если не монтировать `CreateClubModal` (группа 1), из UI пропадает единственная форма, где выбираются тип доступа, лимит, цена и категория. Остаются настройки клуба, страница клуба, приглашение, «Мои клубы» и мастер наполнения.
