# Спринт 1.0 — разворот на плагин к чату

> Дата решения: 2026-08-16. Основание: пять месяцев разработки, ноль живых клубов,
> ноль событий продажи. Документ фиксирует решение, план, финансовую модель и гейты.
>
> **Отношение к предыдущим документам.** Не отменяет
> [market-analysis-and-product-strategy-2026-07.md](market-analysis-and-product-strategy-2026-07.md)
> и [strategy-simple-summary-2026-07.md](strategy-simple-summary-2026-07.md) — они остаются
> верны по анализу рынка. Меняется только **порядок выхода**: стратегия A («Книжная Москва»,
> клубы вперёд) откладывается, активируется стратегия C в переработанном виде — не как второй
> продукт, а как другая точка входа в тот же движок.

## 1. Решение

**Продукт позиционируется как плагин к существующему телеграм-чату, а не как каталог клубов.**

Ничего не переписывается и не удаляется. Меняется точка входа: сначала подключается чат,
клуб создаётся из него сам. Каталог прячется из навигации, роуты остаются живыми.

### Почему это сильнее прежнего позиционирования

1. **Перестаём воевать со статус-кво.** Анализ рынка называл главным конкурентом привычку
   «чат + гугл-таблица + СБП». Прежняя модель просила людей выйти из чата в отдельное
   приложение — самый дорогой из возможных запросов. Новая модель чат не заменяет, а
   апгрейдит: цена переключения падает с «переезжай» до «добавь бота».
2. **Исчезает двойной cold start.** Каталог не работает без плотности клубов в городе;
   инструмент даёт ценность на первом же чате, в вакууме.
3. **Появляется виральный след.** Каждое сообщение бота видят 50–500 участников чата, часть
   из них админит другие чаты. У каталога такой петли не было в принципе («клуб живёт в
   своём чате, наружу ничего не торчит»).
4. **Предложение помещается в рекламный пост.** «Бот, который ведёт встречи в вашем чате»
   продаётся постом. «Платформа для платных офлайн-клубов с репутацией» требует разговора.
   Это структурное свойство, копирайтингом не лечится, и оно определило выбор канала.
5. **Счёт становится частью продукта.** В прежней модели тариф FREE покрывал типового
   организатора навсегда — сценарий смерти по версии скептика: «убийца — невыставленный
   вовремя счёт». В чат-модели подписка и есть продукт.

### Что НЕ меняется

- Клуб остаётся отдельной сущностью — это штаб-квартира чата, а не синоним чата.
- **Глобальная личность пользователя и репутация сквозь чаты сохраняются.** Это единственный
  мост обратно к платформе (Фаза 3–4). Упрощать до данных внутри чата — запрещено.
- Отвергнутое ранее остаётся отвергнутым (см. § 9).

### Чего нет (проверено)

| Пробел | Оценка |
|---|---|
| Инвертированный онбординг: сейчас клуб создаётся формой, потом привязывается чат | 2–3 дня |
| Авто-членство из чата (`new_chat_members`/`left_chat_member` не обрабатываются) | 5–7 дней |
| Голосование `callback_data`-кнопками в чате (сейчас только url-кнопка в Mini App) | 8–12 дней |
| Биллинг под модель «за чат» (`SubscriptionPlanPolicy` считает **платные клубы**) | 5 дней |
| Повторяющиеся встречи / расписание (шаблоны есть, расписания нет) | 7–10 дней |

**Платформенное ограничение:** Bot API не отдаёт список участников группы (только админов и
счётчик). База участников наполняется лениво, по мере нажатий. Обещать админу полную явку по
всему чату в первый день нельзя.

**Цена самого разворота: ~1 150 строк прод-кода.** Не тридцать тысяч. Разница между оценкой
и страхом — объём обязательной обвязки (§ 8), а не сложность кода.

## 3. Модель развития: четыре продукта

**Инструмент → Штаб → Сеть → Рынок.** Каждая фаза окупается сама и не требует веры в следующую.

| | Что продаём | Кому | Почему платят |
|---|---|---|---|
| **Ф1. Инструмент** | бот ведёт встречи в вашем чате | админу чата | рутина исчезла |
| **Ф2. Штаб** | штаб-квартира сообщества | ему же | взносы, чеки НПД, память, аналитика |
| **Ф3. Сеть** | ваш чат связан с другими | админу, который хочет расти | приток людей с историей |
| **Ф4. Рынок** | найди своих | участнику | исходное видение |

Ключевое свойство: Ф1 копит чаты, Ф2 копит историю явки, Ф3 копит связи между чатами,
Ф4 продаёт накопленное. **Двойной cold start, убивавший исходную модель, к Ф4 решён самим
ходом развития.**

### Финансовая модель

Допущения: база 300 ₽/мес за чат; тариф «Клуб» 700 ₽ (взносы, должники, чеки НПД, аналитика,
несколько чатов) вводится в Ф2; консьерж-сопровождение 20 000 ₽/мес; отток 8% → 5%.

| Веха | Чатов | MRR |
|---|---|---|
| Ф0, месяц 1 | 10 | 3 000 ₽ |
| Ф1, месяц 6 | 191 | 57 300 ₽ + консьерж 60 000 = **117 000 ₽** |
| Ф2, месяц 12 | 684 (25% на «Клубе») | 274 000 ₽ + консьерж 100 000 = **374 000 ₽** |
| Ф3, год 2 | 1 800–2 500 | **~1 150 000 ₽** |

**Юнит-экономика:** LTV базы 3 600–6 000 ₽ при сроке жизни 12–20 месяцев. CAC посевами
300–800 ₽, окупаемость 1–3 месяца. Аутрич — 0 ₽ деньгами, ~1,7 часа на клиента.

**Модель рушится в одном месте:** если отток окажется 15% вместо 8%, срок жизни падает до
6 месяцев, LTV до 1 800 ₽, платные каналы перестают окупаться. **Отток мерить с первой
когорты.**

**Безубыточность** (расходы + 150 000 ₽ основателю): месяц 11–13, ~700 чатов.

**Главный финансовый вывод: первый год не кормит.** Консьерж-контракты финансируют разработку,
self-serve строит актив. Три сделки в месяце 4 дают больше, чем весь self-serve первого
полугодия. Путать их нельзя: консьерж не масштабируется, self-serve не кормит.

## 4. Спринт 1.0 — план

**Критерий готовности: человек с рекламного поста доходит от клика до оплаты, ни разу не
упершись в экран, который надо объяснять.** Всё, что не на этом пути, — не в спринте.

| День | Работа | Зачем |
|---|---|---|
| **0** (1,5 ч) | Короткий флоу для малых правок в CLAUDE.md; `docs/backlog` вне alignment | иначе каждая правка ниже стоит вдвое |
| **0,5** | Индекс доков `docs/INDEX.md` | окупается за 10 правок этого же спринта |
| **1** | Discovery из дока, `/` ведёт в клуб, объект `PRODUCT_PROFILE` | первый экран перестаёт отвечать не на тот вопрос |
| **2–3** | `?startgroup=new` → клуб создаётся из чата сам, бесплатным, + вопрос про город | **блокирует всё остальное** |
| **4** | Экран оплаты: реквизиты, ручной приём. Тумблер «собирать взнос» — выкл. | без счёта реклама бессмысленна |
| **4,5** | Разметка воронки: `?start=ad_<кампания>` + счётчики по шагам | без неё реклама — лотерейный билет |
| **5–6** | Онбординг: экран админа «подключите чат» + тексты участника под чат | снимает вопрос «какие клубы?» |
| **7–11** | AI-опрос v0 (см. § 5) | то, ради чего реклама интересна |

**Порядок неслучаен:** клуб из чата вторым, потому что от него зависят онбординг, оплата и
город для ИИ. AI последним, потому что его можно резать на ходу, не ломая остальное.

**Срок: ~11 рабочих дней + staging-циклы = 2,5 недели, ориентир 5 сентября.** Дата, а не
состояние: состояние отодвигается бесконечно и всегда по уважительной причине.

**Порядок резки при отставании:** настройки AI → предохранители от выгорания → полировка
текстов онбординга. **Не режется:** клуб из чата, экран оплаты, разметка воронки.

### Ключевые технические решения спринта

- **Клуб из чата рождается бесплатным** (`subscription_price = 0`). Код уже везде ветвится на
  `subscriptionPrice > 0` — вся машинерия взносов гаснет сама, отдельной работы не требует.
- **Платные клубы не удаляются**, а убираются из дефолтного пути: раздел «Взносы и реквизиты»
  прячется за тумблер, выключенный по умолчанию.
- **Складчина не трогается** — разовый сбор на встречу идеально ложится на чат и остаётся
  одной из главных продающих фич.
- **Discovery гасится в навигации, роуты живые** — deep link'и не ломаются.
- **`PRODUCT_PROFILE`** — один объект на весь UI, не флаг на фичу. Развилка, не менявшаяся
  полгода, схлопывается: победивший вариант зашивается, флаг удаляется.

## 5. AI-опрос — киллер-фича, разбор

**Механика v0:** во вторник бот запускает мультиответный опрос (когда удобно + тип отдыха:
активный / пассивный / на природе / в городе) → ИИ по ответам и городу чата предлагает
**три формата отдыха** → админ выбирает один → создаётся встреча и уходит на голосование.

**Ценность не в подборе заведений**, а в двух других вещах:

1. **Ритм.** У бота появляется причина существовать каждую неделю, а не только когда есть
   встреча. Сейчас в чате без запланированной встречи он молчит — подписка ощущается как
   оплата тишины.
2. **Снятие выбора с админа.** «Придумай, найди место, назначь, собери» → «выбери из трёх».
   Бьёт в главную причину смерти чатов — усталость организатора.

Плюс третье: **это единственная фича, продающаяся одной строкой.**

### Решение: без поиска заведений в v1

LLM знает заведения приблизительно и уверенно предложит место, закрывшееся год назад.
**Одна галлюцинация в живом чате убивает доверие навсегда** — виноват будет админ, который
это переслал. Настоящие источники дороги: 2ГИС запрещает хранение, Яндекс ППО от 195 000 ₽/год,
геосаджест не отдаёт координат.

**ИИ предлагает форматы, а не места** («велопрогулка с пикником», «поход 10–12 км»,
«спортивные игры + чай»). Место выбирают люди в чате — они знают его лучше любого API.
Галлюцинировать не в чем: формат — предложение, а не факт. Ценность падает на ~20%,
риск и стоимость — до нуля. Реальные места — v2, при платящих клиентах.

### Обязательные предохранители

- **Порог мандата:** не предлагать варианты, пока не ответили ≥5 человек или ≥10% чата.
- **Затухание:** два опроса подряд без ответов → бот замолкает и пишет админу.
- **Опрос внутри живого закрепа**, не отдельным постом (бюджет: 1 закреп + максимум 2 поста
  в день — жёсткий инвариант для всех чат-фич).
- **Частота настраивается**, лучше привязана к «прошло N дней с последней встречи».
- **Админ не выбрал** → напоминание через сутки, дальше тишина до следующего вторника.
  Бот не назначает встречу сам.
- **Город чата спрашивается при подключении** — иначе фича не работает вообще.

**Стоимость ИИ:** один вызов на чат в неделю; при 700 чатах ~3 000 вызовов/месяц. На Haiku —
доллары. Не является статьёй риска.

**Privacy mode остаётся включённым:** ИИ видит только ответы на опрос и город. «Бот не читает
ваши сообщения» — аргумент для рекламы.

## 6. После спринта

**Реклама: два креатива по 2 500 показов** в один нормальный канал, а не один на 5 000.
Оба провалились — проблема в продукте или канале. Один выиграл — проблема была в тексте.

**Читать по шагам воронки:** показы → клики → старт бота → чат подключён → оплата.
Обрыв на конкретном шаге — конкретный диагноз. «Не сработало» без разбивки — потерянные деньги.

**Метрики.** Северная звезда — **встреч состоялось**. Не DAU, не время в приложении
(стратегия прямо отвергает фарминг заходов; дашборды притягивают тщеславные метрики
силой гравитации).

Четыре группы: воронка · здоровье чата · когорты удержания · деньги. Самая ценная производная —
**чаты с нулём встреч за 30 дней**: это отток, который случится через месяц, но виден уже
сейчас, и единственная метрика, по которой можно действовать заранее.

**Дашборд не строить до ~50 чатов** — при нуле клиентов это артефакт избегания. Вместо него
**воскресный DM от бота самому себе** (полдня, ноль интерфейса, переиспользует
`NotificationService` и шедулеры):

```
Неделя 34
Чатов: 47 (+9, −2)
Платят: 31 · MRR 9 300 ₽
Встреч состоялось: 62
Чатов без встреч 30 дней: 6  ← смотреть сюда
Воронка: 812 кликов → 94 старта → 11 подключений → 4 оплаты
```

**Деньги, календарём а не кодом:** самозанятость — сразу; ИП + ЮKassa запускать в работу на
первой неделе спринта (2–4 недели ожидания, должны идти фоном). Первые десять клиентов
платят переводом вручную.

## 7. Гейты

Прогнозы врут, гейты — нет. Каждый ловит конкретную ложь.

| Переход | Гейт | Что ловит |
|---|---|---|
| Ф0 → Ф1 | **10 платящих, 6 продлились на второй месяц** | «продукт нравится, но не нужен» |
| Ф1 → Ф2 | >50% подключаются без основателя; отток <8%; CAC <800 ₽ | «работает только когда ты рядом» |
| Ф2 → Ф3 | ≥15% чатов имеют общего человека с другим подключённым чатом | «сеть не завяжется» |
| Ф3 → Ф4 | ≥25% вступлений от людей с досье из другого чата | «платформы не будет» |

Гейт не пройден — остаёмся на текущей фазе и чиним причину, а не идём дальше по плану.

## 8. Диагноз: что на самом деле замедляет разработку

**Проверено цифрами: замедляет не размер кода.** 50 тысяч строк — не большой проект,
пропускная способность не упала (19 PR за 17 дней с 30 июля по 15 августа).

**На каждую строку прод-кода приходится 1,6 строки обязательной сверки.** Типичный PR трогает
15–30 файлов, пики — 46, 62, 64, 71. Сам код там на сотни строк; остальное — тесты, спеки,
доки, комментарии.

Источники:

1. **Процесс фиксированной длины.** Фича-флоу — 8 проходов, багфикс — 5. Правка в три файла
   стоит столько же, сколько эпик на 60.
2. **Docs alignment грепает всё** — 157 файлов, 36 тысяч строк, и стоимость растёт с каждой
   сделанной фичей.
3. **`docs/backlog` — 10 138 строк архива**, участвующего в сверке наравне с живыми спеками.

**Лечение (по убыванию отдачи):** урезать процесс под размер правки → индекс вместо грепа →
вынести архив из зоны сверки → `PRODUCT_PROFILE` вместо релизной ветки.

**Рефакторинг кода ради скорости не делать** — цифры показывают, что он не является узким
местом. Потратит недели и не изменит ощущение, потому что причина в другом слое.

**Релизная ветка «только чат» отвергнута:** долгоживущая ветка = порт каждого фикса дважды,
дублирование состояний, слом правила «ничто не идёт в master минуя staging». Решает ту же
задачу, что один флаг в конфиге, в тысячу раз дороже.

## 9. Отвергнутое — не реанимировать

| Что | Почему |
|---|---|
| **Процент со взносов участников** | организаторы уведут оплаты мимо продукта и сломают все данные |
| **Деньги с участников** | каждый участник на вес золота, любой рубль на входе лишний |
| **Репутация за платную подписку** | единственное, чего нет у конкурентов, должно быть бесплатным |
| **Поиск заведений ИИ в v1** | галлюцинации убивают доверие; POI стоит от 195 000 ₽/год |
| **Нативный Telegram poll** | голос не привязан к личности так, как нужно очереди и репутации |
| **Команды бота в чате** (`/встреча`, `/кто @user`) | превращают продукт в утилиту; чат = 3 касания (закреп, кнопка, итог), работа — в приложении |
| **Публичные числовые рейтинги в чате** | в компании, где все видятся лицом к лицу, дно таблицы = обида и уход |
| **Ленты, реакции, обсуждения в приложении** | с Telegram в разговоре не поспоришь |
| **Релизная ветка «только чат»** | см. § 8 |
| **Дашборд до ~50 чатов** | артефакт избегания, показывает нули |

## 10. Честная оценка шансов (2026-08-16)

| Этап | Вероятность | Основание |
|---|---|---|
| Плагин будет построен | **95%** | 145 PR за 5 месяцев, чат-слой готов на 75% |
| Аутрич/реклама реально случится | **~62%** | план дважды не исполнялся, но канал наконец выбран тот, в который есть вера |
| 10 платящих, если случится | **~70%** | просьба дешёвая, продукт сильный, боль настоящая |
| **→ первые деньги** | **~41%** | |
| **→ работающий бизнес** (~700 чатов) | **~17%** | отток, эквайринг, выгорание, bus factor 1 |
| **→ итоговая платформа** | **~4%** | |

**17% на работающий бизнес — хорошая ставка**, потому что низ ограничен: даже в проигрышном
сценарии остаётся продукт и приобретённый навык продажи.

**Главный множитель — не рынок и не код**, а состоится ли просьба о деньгах. Это единственная
строка таблицы, зависящая только от основателя.

**Что сдвигает оценку:** один посторонний человек, заплативший настоящие деньги. Это событие
переводит шанс на бизнес с 17% к 25–30%. Ни одна фича не сдвигает оценку и близко так сильно.

### Ключевые риски с ценниками

| Риск | Цена | Что делать |
|---|---|---|
| Эквайринга нет (`StubPaymentProvider`) | блокирует всё | самозанятость + переводы для первых 10; ИП + ЮKassa параллельно |
| Отток выше прогноза | обрушивает LTV вдвое | мерить с первой когорты; при >12% снимать платные каналы |
| Bus factor = 1 | остановка при болезни | разработчик №2 с месяца ~13, раньше нечем платить |
| Блокировки Telegram | продукта нет | не лечится, принять как условие |
| Яндекс.Карты POI | от 195 000 ₽/год | не включать до Ф2, геосаджест бесплатен |
| Сеть не завяжется (Ф3) | потолок ~1,15 млн ₽/мес | это работающий бизнес, а не провал; Ф4 просто не наступает |

## 11. Что сознательно не делаем в спринте 1.0

Голосование `callback`-кнопками в чате (остаётся deep link в Mini App — и это полезно, человек
попадает в приложение) · бэкфилл «отметься» · расписание на автопилоте · доска идей ·
условное согласие «пойду, если пойдёт кто-то из моих» · встреча новичка · перенос секций
«Мои клубы» внутрь клуба · профиль/XP · дашборд · любой рефакторинг.

Всё хорошее. Ничто не влияет на путь от клика до оплаты.

## 12. Бэклог следующих фич (после первых денег)

Приоритет — по причинам, почему в чате редко встречаются, а не по типам фич.
Метрика одна: **встреч стало больше**.

| Причина | Фича | Оценка |
|---|---|---|
| Организатор — горлышко | встречу создаёт **любой участник** (сейчас гейт `MANAGE_EVENTS`) | 4 дня |
| | лёгкий формат «зов» (2 поля, поверх существующей «открытой встречи») | 4 дня |
| | расписание на автопилоте | 7–10 дней |
| Идеи тонут в чате | **доска идей** с голосами → порог → встреча одной кнопкой | 8 дней |
| | «повторить» из истории встречи | 2 дня |
| «Не с кем идти» | **условное согласие** «пойду, если пойдёт кто-то из моих» | 5 дней |
| | «из идущих ты знаешь четверых» (по пересечениям посещений) | 2 дня |
| | гость +1 | 4 дня |
| Не знают, когда удобно | подбор даты карточкой в приложении | 4 дня |
| Новичок не доходит | карта клуба · встречающий на первую встречу | 5 + 3 дня |
| Чат не помнит | летопись клуба · твоя история в клубе | 5 + 3 дня |
| Деньги админа | **помощник с чеками НПД** — нет ни у кого, аудитория совпала точно | 7 дней |
| | автодожим должников (с кнопкой «этого не трогать») | 5 дней |
| Мелочи с высокой отдачей | `sendVenue` (гео есть, примитив не используется) · утренний дайджест админу · тумблеры «что бот постит» | 1 + 2 + 2 дня |

**Топ-3, если брать сразу после спринта:** доска идей · встречу создаёт любой участник ·
условное согласие. Три недели, и это ответ админу на «зачем мне бот»: **встреч стало больше,
а я делал меньше.**
