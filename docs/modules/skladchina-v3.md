## 0. Словарь

| Термин | Смысл |
|---|---|
| **Сбор** | Повод и обёртка: название, вид, срок, реквизиты, чат-пост, пачка долгов |
| **Долг** | Запись «кто → кому · сколько · за что (сбор) · до какого · состояние» |
| **Получатель** | Тот, кому идут деньги. По долгам сбора это его создатель |
| **Должник** | Тот, кто платит |
| **Пара** | Два человека и все открытые долги между ними в обе стороны |
| **Сальдо пары** | Разница сумм открытых долгов пары. Считается только внутри пары |
| **Открытый долг** | В состоянии `waiting`, `promised` или `claimed` |

## 1. Принципы, об которые проверяется каждое правило

Принципы PO (2026-09-12), по приоритету выше принципов приложения:

1. Организатор сбора не остаётся в минусе: сначала собрать, потом гарантировать. Исключение:
   событие уже прошло.
2. Сборы должны с высокой вероятностью собираться.
3. У всех должна быть мотивация закрыть свой долг.
4. Контролирует сбор его создатель и владелец клуба.
5. У кого-то может не быть денег сейчас, ему нужно время. Это допустимо.
6. Всё гениальное просто. Правило, которое нужно объяснять абзацем, неверное.

Принципы приложения: деньги идут напрямую, платформа только ведёт учёт; меньше рутины
организатору; репутация не досье; сбор живёт в чате клуба; одно правило вместо трёх исключений.

## 2. Модель

### 2.1 Сбор (`skladchinas`)

Три вида. Всё, чем принятые сценарии отличаются друг от друга, сводится к одному вопросу:
**откуда берётся долг и что с ним в срок**.

| Вид (`kind`) | Откуда долг | В срок с неоплаченным | Репутация | Сценарии |
|---|---|---|---|---|
| `shared` «Скинуться» | назначает создатель: поровну или суммами по людям; после встречи или до неё через этап «Кто в деле?» | остаётся долгом | да | ужин, корт, бензин, пикник, тренер, инвентарь |
| `per_head` «Кто берёт?» | участник сам жмёт «Беру» | выбывает без долга при «Заказываю» | нет | билеты, мерч, стартовый взнос, призовой фонд |
| `voluntary` «По желанию» | участник жмёт «Перевёл N ₽», долг рождается уже как `claimed` | ничего | нет | подарок, благодарность, поддержка, общак |

Членский взнос это существующий взнос клуба, в сборы не входит.

Поля (новые и изменённые относительно `skladchina.md`):

| Поле | Тип | Смысл |
|---|---|---|
| `kind` | `skladchina_kind` | вид, см. выше. Заменяет пару `template` + `payment_mode` |
| `amount_kopecks` | BIGINT NULL | `shared`: общая сумма; `per_head`: цена за человека; `voluntary`: ориентир (необязателен). Бывший `total_goal_kopecks` |
| `deadline` | TIMESTAMPTZ NULL | срок оплаты. Обязателен для `shared` и `per_head`, у `voluntary` необязателен |
| `event_id` | UUID NULL | `shared` после встречи: список из пришедших |
| `enrollment_until` | TIMESTAMPTZ NULL | `shared` до события: до когда открыт этап «Кто в деле?». NULL = этапа нет, список задаёт создатель |
| `min_participants` | INT NULL | `shared` с этапом: минимум людей, иначе сбор отменяется сам |
| `locked_at` | TIMESTAMPTZ NULL | момент заморозки списка и создания долгов (`shared` с этапом) |
| `ordered_at` | TIMESTAMPTZ NULL | `per_head`: «Заказываю» нажато, приём закрыт |
| `hidden_from_user_id` | UUID NULL | `voluntary`: от кого скрыть (именинник). Скрытый сбор **тихий**: чат-поста нет, DM всем, кроме скрытого |
| `status` | `skladchina_status` | `active` · `collected` · `cancelled`. Старые `closed_success`/`closed_failed` исчезают |
| `payment_link`, `payment_method_note`, `title`, `description`, `photo_url`, `reminder_sent_at` | | без изменений |

Удаляются: `payment_mode`, `affects_reputation` (следует из вида), `template`
(`split_bill` = `shared` + `event_id`), `confirmation_requested_at`, `closed_by`.

**Доля создателя.** Создатель не должен сам себе: его долг создаётся сразу в `received`, чтобы
суммы «получено X из Y» сходились. У `per_head` создатель может «взять» вещь как все, его долг
тоже сразу `received`. У `voluntary` создатель просто не создаёт себе долг.

**Итог сбора.** `active` → `collected`, когда нет открытых долгов (для `per_head` дополнительно
`ordered_at IS NOT NULL`, для `voluntary` только рукой). `cancelled` только рукой. Порогов,
процентов и «не собран» нет.

### 2.2 Долг (`debts`)

| Поле | Тип | Смысл |
|---|---|---|
| `id` | UUID | |
| `skladchina_id` | UUID FK | за что |
| `debtor_id`, `creditor_id` | UUID FK users | кто → кому. `creditor_id` = создатель сбора |
| `amount_kopecks` | BIGINT > 0 | сколько |
| `due_at` | TIMESTAMPTZ NULL | копия `deadline` сбора на момент создания; NULL у `voluntary` |
| `status` | `debt_status` | см. состояния |
| `promised_at` | DATE NULL | «Оплачу позже»: к какой дате |
| `claimed_at` | TIMESTAMPTZ NULL | когда должник нажал «Отдал» |
| `confirmed_at` | TIMESTAMPTZ NULL | когда получатель нажал «Получил» |
| `rejected_at`, `reject_note` | | последнее «Не получил» и заметка |
| `note` | TEXT NULL | заметка должника: «не согласен с суммой», размер футболки при «Беру» |
| `receipt_url` | TEXT NULL | чек (наше хранилище, проверка `UploadedImageUrls`) |
| `settlement_id` | UUID FK NULL | закрыт в составе сальдо пары |
| `reputation_plus_at`, `reputation_minus_at` | TIMESTAMPTZ NULL | штампы идемпотентности начислений |
| `created_at`, `updated_at` | | |

Уникальность: один долг на пару (`skladchina_id`, `debtor_id`).

**Состояния** (`debt_status`): `waiting` ждём · `promised` обещал к дате · `claimed` должник говорит,
что отдал · `received` получатель подтвердил · `forgiven` получатель простил · `dropped` выбыл
(`per_head`). Открытые: первые три.

**Переходы.** Всё, что можно сделать с долгом, в одной таблице. Что не в таблице, того нет.

| Действие | Кто | Из | В | Побочный эффект |
|---|---|---|---|---|
| создание | сбор | — | `waiting`; доля создателя `received`; у `voluntary` `claimed` | DM должнику |
| «Оплачу позже» {дата} | должник | `waiting`, `promised` | `promised` | напоминания молчат до даты |
| «Отдал» | должник | `waiting`, `promised` | `claimed` | DM получателю с кнопками «Получил / Не получил»; часы минуса стоят |
| «Отменить» | должник | `claimed` | `waiting` | |
| «Получил» | получатель | `waiting`, `promised`, `claimed` | `received` | сбор проверяет закрытие; плюс, если вовремя (§ 4). Без предшествующего «Отдал» это наличные |
| «Не получил» {заметка} | получатель | `claimed` | `waiting` | `rejected_at`; DM должнику «приложите чек» |
| «Простить» | получатель | `waiting`, `promised`, `claimed` | `forgiven` | сбор проверяет закрытие |
| «Изменить сумму» | получатель | `waiting`, `promised` | то же | только `shared`; DM должнику |
| «Заменить» {userId} | создатель | `waiting`, `promised` | `forgiven` + новый долг у замены с той же суммой | только `shared`; DM обоим |
| «Передумал» | должник | `waiting`, `promised` | `dropped` | только `per_head` до `ordered_at` |
| «Заказываю» | создатель | `waiting`, `promised` | `dropped` | только `per_head`; DM выбывшим; `claimed` остаются, их надо разобрать |
| отмена сбора | создатель, владелец | все открытые | `forgiven` | `received` не трогаем, создателю показываем список «кому вернуть» |
| сальдо «Отдал» | должник по сальдо | все открытые долги пары | `claimed` + `settlement_id` | один DM получателю |
| сальдо «Получил» | получатель по сальдо | все `claimed` этого `settlement_id` | `received` | встречные долги получателя тоже `received` (зачтены) |
| сальдо «Не получил» | получатель по сальдо | все `claimed` этого `settlement_id` | `waiting` | `settlement.status = rejected` |

### 2.3 Сальдо пары (`debt_settlements`)

Сальдо пары A ↔ B = Σ открытых долгов A → B − Σ открытых долгов B → A. Кнопка сальдо это
«Отдал» разом по всем открытым долгам пары; подтверждает получатель разницы, как в одиночном
долге. Между разными людьми ничего не схлопывается (цепочки A → B → C не сводятся).

| Поле | Смысл |
|---|---|
| `id`, `payer_id`, `payee_id` | кто переводит разницу кому |
| `amount_kopecks` | разница на момент «Отдал» |
| `status` | `claimed` · `received` · `rejected` |
| `claimed_at`, `resolved_at` | |

Пока сальдо в `claimed`, одиночные кнопки у долгов пары скрыты, чтобы не было двух параллельных
подтверждений одного и того же.

### 2.4 Права

| Кто | Что может |
|---|---|
| любой активный участник клуба | создать сбор любого вида; «В деле», «Беру», «Перевёл», «Отдал», «Оплачу позже», «Передумал», чек, заметка по своим долгам |
| создатель сбора | всё по сбору: закрыть запись, «Заказываю», «Закрыть» (voluntary), отменить, изменить сумму, заменить, «Получил» / «Не получил» / «Простить» по долгам сбора |
| владелец клуба, со-организаторы с `MANAGE_SKLADCHINA` | отменить чужой сбор. Долгов не видят |
| скрытый (`hidden_from_user_id`) | не видит сбор нигде: ни в ленте, ни по прямой ссылке (404), ни в DM |

Экран «Долги» показывает только долги, где я одна из сторон. Чужих долгов не видит никто,
включая владельца клуба.

## 3. Жизненные циклы по видам

### 3.1 `shared` после встречи

Вход: страница прошедшей встречи, кнопка «Скинуться» (также «+» в «Активностях»). Список =
пришедшие (`event_responses.attendance = attended`, только активные участники клуба), правится
руками. Сумма общая; доли поровну (`SkladchinaShares.equal`, остаток копеек последнему по id) или
суммами по людям. Доля создателя `received`. Долги создаются сразу, `due_at = deadline`.
Одно ограничение с сегодняшнего сплита остаётся: встреча не старше 30 дней и без другого
активного сбора по ней.

### 3.2 `shared` до события

Если задан `enrollment_until` (и, опционально, `min_participants`): создаётся без долгов, в чат
уходит пост «Кто в деле?» с кнопкой. Участники жмут «В деле» / «Передумал» (запись, не долг).
Заморозка (`locked_at`) наступает по `enrollment_until` шедулером или раньше рукой создателя
(«Закрыть запись»). При заморозке: если в деле меньше `min_participants` → `cancelled`, чат-пост
«Не набрали», DM создателю, денег никто не переводил. Иначе доли = `amount / N`, долги созданы,
DM каждому, чат-пост меняется на обычный. Создатель в списке по умолчанию.

Без `enrollment_until` список задаёт создатель, долги сразу, как в 3.1.

Замена выбывшего после заморозки: «Заменить» (§ 2.2). Доли не пересчитываются никогда.

### 3.3 `per_head`

Создаётся с ценой и сроком; чат-пост с кнопкой «Беру». «Беру» {заметка} создаёт долг
`waiting`; «Передумал» → `dropped` до `ordered_at`. Оплата как везде: «Отдал» → «Получил».
«Заказываю» (создатель, в любой момент): диалог называет «получено N, не оплатили K, они
выбывают», `waiting`/`promised` → `dropped` с DM, `ordered_at` ставится, приём закрыт, «Беру»
больше недоступно. `claimed` при заказе остаются: создатель разбирает их «Получил» /
«Не получил» (после заказа «Не получил» = `dropped`). `collected`, когда после заказа нет
открытых. Автозаказа по сроку нет: заказ это действие в жизни; создателю напоминание в срок и
раз в день после.

### 3.4 `voluntary`

Создаётся с ориентиром (необязательно), сроком (необязательно), «скрыть от» (необязательно).
Участник жмёт «Перевёл N ₽»: долг рождается сразу `claimed` на N. Получатель «Получил» /
«Не получил». Напоминаний должникам нет. Закрывается только рукой создателя («Закрыть сбор»),
при наличии `claimed` кнопка недоступна с подсказкой «разберите N переводов». Скрытый сбор:
чат-поста нет, DM всем активным участникам, кроме скрытого; скрытый не видит сбор нигде.

## 4. Репутация

Только у долгов сбора вида `shared`. Начисляет шедулер по штампам `reputation_plus_at` /
`reputation_minus_at`, идемпотентно.

| Событие | Очки | Условие |
|---|---|---|
| долг `received` вовремя | `skladchina_paid` (+10) | `coalesce(claimed_at, confirmed_at) <= due_at` |
| долг `received` с опозданием | 0 | |
| долг `forgiven`, `dropped` | 0 | |
| просрочка | `skladchina_expired` (−40), один раз | статус `waiting`/`promised` и `now > max(due_at, rejected_at) + DEBT_OVERDUE_WEEKS`; `claimed` не считается: часы стоят, пока получатель молчит |
| оплата после минуса | ничего дополнительно | минус остаётся фактом просрочки |
| зачтено по сальдо | как `received` | `claimed_at` сальдо считается моментом оплаты |

`DEBT_OVERDUE_WEEKS = 3` (константа, предложение). Владелец клуба в своём клубе очков не
получает (существующее правило леджера). Тумблер «важный сбор» и лимит важных сборов удалены:
репутация следует из вида, а +10 можно получить только по реальному долгу перед реальным человеком.

## 5. Напоминания и шедулер

Один шедулер `DebtScheduler` с периодом из конфига (`debts.poll-ms`, дефолт 10 мин; на staging
ускоряется как `SKLADCHINA_CONFIRMATION_POLL_MS` сегодня). Все напоминания идемпотентны по
штампам на долге или сборе.

| Кому | Когда | Текст (суть) |
|---|---|---|
| должник (`waiting`) | за 24 ч до `due_at` | «завтра срок: 857 ₽ Оле за тренера» |
| чат клуба | за 24 ч до `deadline` сбора | существующее напоминание с упоминаниями (не тихий сбор) |
| должник (`waiting`) | в день `due_at`, затем раз в 7 дней | «долг 1 000 ₽ Ивану, срок был 20.09» |
| должник (`promised`) | в `promised_at` | «вы обещали к сегодня» |
| получатель (`claimed` > 48 ч) | раз в 3 дня | «Саша говорит, что отдал, ответьте» с кнопками |
| создатель `per_head` | в `deadline` и раз в день, пока нет `ordered_at` | «пора заказывать: получено N» |
| создатель `shared` с этапом | в `enrollment_until` | «в деле N, список заморожен» / «не набрали» |
| минус за просрочку | § 4 | DM должнику «репутация снижена» |

Кнопки в DM «Получил / Не получил» это inline callback-кнопки (механика уже есть:
`RosterCallbackService`, `ChatLinkBotService`). Ответ из DM равносилен нажатию в приложении.

## 6. Чат-пост и DM

Пост бота в чате клуба это главный экран сбора; перерисовывается на каждое изменение долга
(существующий `SkladchinaProgressChangedEvent` → `SkladchinaChatStatusService`). Скрытый
`voluntary` поста не имеет.

| Вид, стадия | Пост |
|---|---|
| `shared`, идёт | «🍽 Ужин после игры · по 1 000 ₽ с человека · собирает Иван · полоса 🟩⬜ · 💵 Получено X из Y ₽ · оплатили N из M · ⏳ До <дата> · Ждём: @… · [Открыть сбор]» |
| `shared`, этап «Кто в деле?» | «🎾 Тренер на субботу · 6 000 ₽ на группу, поровну между теми, кто в деле · 👥 В деле N · нужно K · ⏳ Отметиться до <дата> · В деле: @… · [В деле]» |
| `shared`, после срока | те же числа, «⏳ Срок вышел», строка с именами по § 12-1 |
| `shared`, `collected` | «✅ … · собрано Y ₽ · оплатили M из M» |
| `shared`, не набрали | «Не набрали: в деле N из K. Сбор отменён, денег никто не переводил» |
| `per_head`, идёт | «🎫 Билеты на матч · 1 500 ₽ за билет · <создатель> покупает <дата> на тех, кто оплатил · 👥 Берут N · оплатили K · ⏳ До <дата> · [Беру]» |
| `per_head`, заказано | «✅ … · куплено N · Y ₽ · приём закрыт» |
| `voluntary` (не тихий) | «🎁 … · по желанию, ориентир 500 ₽ · до <дата> · собирает <имя> · [Открыть]» |
| любой, `cancelled` | «Сбор отменён» |

Полоса: 🟩 получено, 🟨 говорят, что отдали, ⬜ ждём; десять ячеек, доля по деньгам.

DM: создание (по виду, с реквизитами и кнопкой в Mini App), запрос подтверждения «Отдал» с
inline-кнопками, «Не получил» должнику, выбывание из `per_head`, напоминания § 5, итог сбора

## 8. Схема БД и миграция

Миграции с **V90** (V87/V88 заняты локальной веткой биллинга, V89 веткой сверки оплат; при
любом порядке мержа номера не пересекаются).

**V90__skladchina_v3.sql**, одним файлом:

1. Новые типы: `skladchina_kind` (`shared`, `per_head`, `voluntary`); `debt_status` (`waiting`,
   `promised`, `claimed`, `received`, `forgiven`, `dropped`); `debt_settlement_status`
   (`claimed`, `received`, `rejected`); `skladchina_status_v3` (`active`, `collected`,
   `cancelled`), который заменяет старый `skladchina_status`.
2. `skladchinas`: добавить `kind`, `enrollment_until`, `min_participants`, `locked_at`,
   `ordered_at`, `hidden_from_user_id`; переименовать `total_goal_kopecks` → `amount_kopecks`;
   заполнить `kind` из старых полей (`split_bill` или `fixed_*` → `shared`, `voluntary` →
   `voluntary`); сменить тип `status` с маппингом (`closed_success` → `collected`,
   `closed_failed` → `cancelled`); убрать колонки `payment_mode`, `affects_reputation`,
   `template`, `confirmation_requested_at`, `closed_by` и старые типы.
3. Создать `debts` (§ 2.2) и `debt_settlements` (§ 2.3), индексы по `debtor_id`,
   `creditor_id`, `skladchina_id`, `status`.
4. Перенос `skladchina_participants` → `debts`: `paid`/`payment_confirmed` → `received`,
   `pending`/`payment_rejected`/`payment_disputed` открытых сборов → `waiting`, остальное →
   `forgiven`. После переноса таблица участников и её enum-тип удаляются.
5. `COMMENT ON` на русском для каждой таблицы, колонки и типа (конвенция).

После миграции: `./gradlew generateJooq` по рецепту временного PG, exhaustive `when` по новым
enum проверяет компилятор.

## 11. Критерии приёмки

**AC-1. Скинуться после встречи.** GIVEN встреча с отмеченной явкой, 6 пришедших, создатель
среди них WHEN создаёт `shared` на 6 000 ₽ поровну THEN 6 долгов по 1 000 ₽, долг создателя
`received`, чат-пост «получено 1 000 из 6 000 · оплатили 1 из 6 · Ждём: 5 упоминаний», 5 DM.

**AC-2. Отдал → Получил.** GIVEN долг `waiting` WHEN должник «Отдал» THEN `claimed`, получателю
DM с кнопками; WHEN получатель «Получил» (из DM или приложения) THEN `received`, долг исчез из
`/debts` у обоих, пост перерисован.

**AC-3. Не получил.** GIVEN `claimed` WHEN получатель «Не получил» с заметкой THEN `waiting`,
`rejected_at`, должнику DM, в строке «приложите чек»; должник грузит чек → `receipt_url` виден
получателю в строке.

**AC-4. Закрытие само.** GIVEN сбор `shared`, последний открытый долг WHEN «Получил» или
«Простить» THEN сбор `collected`, DM создателю, пост «✅ собрано».

**AC-5. Срок не стена.** GIVEN `due_at` в прошлом WHEN должник «Отдал» THEN 200 и `claimed`
(не 400). Строка и пост показывают «срок вышел».

**AC-6. Оплачу позже.** GIVEN `waiting` WHEN «Оплачу позже» на дату D THEN `promised`,
напоминания до D не приходят, в D приходит одно; у получателя «обещал к D».

**AC-7. Кто в деле?** GIVEN `shared` с `enrollment_until` и `min_participants = 6` WHEN к сроку
в деле 7 THEN долги по `amount / 7`, DM, пост обычный; WHEN в деле 4 THEN `cancelled`, пост
«не набрали», долгов нет.

**AC-8. Заказываю.** GIVEN `per_head`, 8 `received`, 2 `waiting` WHEN «Заказываю» THEN 2 →
`dropped` с DM, `ordered_at`, «Беру» → 400, пост «куплено 8». Репутация ни у кого не меняется.

**AC-9. Тихий сбор.** GIVEN `voluntary` с `hidden_from_user_id = Маша` THEN поста в чате нет,
DM всем, кроме Маши; для Маши `GET /api/skladchinas/{id}` → 404, в ленте сбора нет.

**AC-10. Сальдо пары.** GIVEN Саша → Кристина 1 000 и 857 `waiting`, Кристина → Саша 400
`waiting` WHEN Саша «Отдал» сальдо THEN settlement 1 457 `claimed`, три долга `claimed` с
`settlement_id`, одиночные кнопки скрыты, Кристине один DM; WHEN Кристина «Получил» THEN все три
`received`, пара пуста у обоих; WHEN «Не получил» THEN все три снова `waiting`.

**AC-11. Репутация.** GIVEN `shared`, долг `received` с `claimed_at <= due_at` THEN +10 один раз;
GIVEN `waiting` и `now > due_at + 3 недели` THEN −40 один раз и DM; GIVEN `claimed` дольше
3 недель THEN минуса нет; GIVEN владелец клуба THEN очков нет.

**AC-12. Чужие долги невидимы.** GIVEN владелец клуба, не сторона долга WHEN `GET
/api/debts/with/{userId}` за пару других людей THEN 403; в «Управлении» долгов нет.

**AC-13. Права на отмену.** GIVEN сбор участника Пети WHEN владелец клуба `cancel` THEN 200,
открытые долги `forgiven`, создателю список «кому вернуть» из `received`; WHEN другой участник
THEN 403.

**AC-14. Сортировка пары.** GIVEN три долга с разными `due_at` THEN в группе порядок по
возрастанию `due_at`, `NULL` последними.

## 12. Открытые вопросы

1. **Имена в чате после срока.** До срока «Ждём: @…» (напоминание). После срока предложение:
   только числа («не оплатили 2»), имена видят получатель и сам должник. PO не решил.
2. **`DEBT_OVERDUE_WEEKS = 3`** и размер плюса/минуса: оставить 10/40 или пересмотреть.
3. **Отмена чужого сбора со-организатором.** PO назвал владельца; спека даёт и
   `MANAGE_SKLADCHINA`, как у остальных менеджерских действий. Подтвердить или сузить.
4. **`voluntary` с неразобранными `claimed`** при закрытии: кнопка недоступна (спека) или
   закрывать с автоподтверждением.
5. **Стратегии.** Спека убирает `SkladchinaTemplateStrategy` в пользу `when (kind)` в двух
   сервисах. Если ветвей станет больше двух мест, вернуть стратегии по видам.
