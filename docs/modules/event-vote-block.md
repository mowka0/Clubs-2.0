# Блок «Набор» на странице события

Спецификация блока голосования Этапа 1 на `EventPage` после редизайна 2026-08-01.
Мокапы и разбор отвергнутых вариантов — [`docs/design/event-vote-redesign/`](../design/event-vote-redesign/README.md).
Фазовая логика показа состава (Этап 1 vs Этап 2) описана в [`events.md`](events.md) и здесь не меняется.

## Зачем

Три дефекта прежнего блока, найденные при разборе:

1. **Кольцо и число внутри него считали разное.** Дуга — доли голосов (`going : maybe : not_going`
   от суммы голосов), число — заполненность мест (`goingCount / participantLimit`). Читались как
   одно целое, поэтому дуга воспринималась как «сколько мест занято».
2. **Кольцо не совпадало по высоте со стопкой кнопок** (168 px против ~130) и торчало из блока.
3. **Лиц за «возможно» и «не иду» не было нигде.** Счётчики есть, а в списке откликнувшихся
   — все вперемешку, различались только цветом точки.

## Что делаем

### 1. Кольцо

- Диаметр **140 px** — ровно высота стопки кнопок (3 × 42 px + 2 зазора по 7 px).
  Высота кнопки фиксируется намеренно: вывести диаметр из содержимого нельзя, ширина кольца
  зависела бы от его высоты, а высота — от высоты строки flex-контейнера (циклическая зависимость).
- Дуга считает **только занятость мест**: `going / participantLimit` на Этапе 1,
  `confirmed / participantLimit` на Этапе 2. Доли голосов кольцом больше не показываются —
  их место в счётчиках кнопок и табах.
- Открытая встреча (`participantLimit = null`): дуга закрашена целиком при `going > 0`,
  при нуле — пустой трек. Знаменателя нет.
- Рисуется SVG (не `conic-gradient`): нужен скруглённый конец дуги.
- Внутри: число + приглушённый знаменатель, под ним капс-подпись «мест занято» / «идут».

#### Объём кольца — стеклом, не неоморфизмом

Основной язык интерфейса — стекло (`--glass-*`: полупрозрачность, hairline, blur). Неоморфизм
(`--neu-lo` / `--neu-hi`) в проекте намеренно заперт в ОДНОМ компоненте — сегментном
переключателе `.rd-seg`: приём работает, только когда объект того же цвета, что фон, поэтому
внутри стеклянных карточек и на светлой теме он разваливается.

Кольцу объём даём стеклянным рисунком: `--ring-groove-shadow` (тень сверху + блик по нижней
кромке, как в `--glass-shadow`) для утопленного жёлоба и градиент `--donut-arc-*` + нейтральная
тень `--ring-arc-shadow` для приподнятой дуги. Акцентную тень пробовали — дуга превращалась
в неоновый ободок.

### 2. Кнопки голоса

- Фиксированная высота 42 px, слева цветная метка-кружок с иконкой (✓ / ? / ✕), справа счётчик.
- Цвет метки и счётчика — цвет голоса (`--vote-go` / `--vote-maybe` / `--vote-no`), подпись
  остаётся цветом текста.
- Выбранный голос — обводка цветом голоса и более плотная поверхность, без сплошной заливки:
  залитая кнопка на тёмной теме читалась как «недоступно».

### 3. «Кто откликнулся» — табы по статусу

Заменяет секцию «Предварительные голоса» на Этапе 1 (`status = upcoming`).

- Три таба: «Идут (N)» · «Возможно (N)» · «Не идут (N)». Переключатель — общий `.rd-seg`.
- Список вертикальный: аватар, имя, точка статуса. Показываются первые 6, дальше —
  «Показать всех · N».
- Данные уже приходят: `GET /api/events/:id/responders` отдаёт всех, у кого есть
  `stage_1_vote` или `final_status`, включая `not_going`. Бэкенд не меняется.
- Ни одного отклика вообще → секции нет, показывается прежняя role-aware строка-намёк (W3-09).
- Отклики есть, но пустой конкретный таб → строка «Здесь пока пусто».
- Этап 2+ (`stage_2` / `completed`) с 2026-08-16 приведён к этому же виду — панель со строками
  вместо сетки, плитки вместо строк «ключ — значение», плюс менеджерский таб «Без ответа»
  и отдельная секция «В очереди»: [`event-stage2-composition.md`](event-stage2-composition.md).

### 4. Бейдж формата в хиро (PO 2026-08-01)

Вместо родового «СОБЫТИЕ» страница показывает конкретный формат встречи — теми же ярлыками
и эмодзи, что карточки лент (`feed/EventCard`, ярлыки PO 2026-07-23), но полными формулировками:

| Условие | Бейдж |
|---|---|
| `isUrgent = true` | ⚡ СРОЧНАЯ ВСТРЕЧА |
| `participantLimit = null` | 🌊 ОТКРЫТАЯ ВСТРЕЧА |
| иначе | 🎟 ВСТРЕЧА С МЕСТАМИ |

`isUrgent` прокинут в `EventDetailDto` (бэкенд: `EventDto.kt` + `EventMapper.toDetailDto`) —
раньше поле отдавалось только в списках, поэтому срочная встреча на своей же странице
выглядела как обычное «СОБЫТИЕ». На карточках лент ярлыки остаются короткими («🎟 ОБЫЧНАЯ») —
там ширины на полную формулировку нет.

- **AC-VB9:** GIVEN срочная встреча THEN бейдж хиро — «⚡ СРОЧНАЯ ВСТРЕЧА».
- **AC-VB10:** GIVEN событие с лимитом, не срочное THEN бейдж — «🎟 ВСТРЕЧА С МЕСТАМИ».

## Критерии приёмки

- **AC-VB1:** GIVEN событие `upcoming`, лимит 20, `goingCount = 12` WHEN открыт `EventPage`
  THEN дуга кольца закрашена на 60 %, внутри «12 / 20» и подпись «мест занято».
- **AC-VB2:** GIVEN то же событие с `maybeCount = 5` WHEN открыт `EventPage`
  THEN голоса «возможно» на заливку кольца не влияют.
- **AC-VB3:** GIVEN открытая встреча (`participantLimit = null`), `goingCount = 9`
  THEN кольцо закрашено целиком, внутри «9» без знаменателя, подпись «идут».
- **AC-VB4:** высота кольца равна высоте стопки кнопок (140 px обе).
- **AC-VB5:** GIVEN событие `upcoming` с откликами `going = 2`, `maybe = 1`, `not_going = 1`
  WHEN открыт таб «Не идут (1)» THEN в списке ровно один человек — проголосовавший `not_going`.
- **AC-VB6:** GIVEN тот же экран WHEN открыт таб с нулём откликов THEN «Здесь пока пусто»,
  а строка-намёк новичка не появляется.
- **AC-VB7:** GIVEN событие `upcoming` без единого отклика THEN секции «Кто откликнулся» нет,
  показана role-aware строка-намёк (поведение W3-09 сохранено).
- **AC-VB8:** GIVEN событие `stage_2` THEN секция называется «Кто идёт», табов нет,
  в списке только `confirmed` (поведение AC-PH1 сохранено).
